# 休沐选 · XiuMuXuan

> 搜一个产品，看它的生产厂家到底休不休双休。

「休沐」是古人对休假的说法。「休沐选」是一个**由用户众包上传**的厂家休息制度事实库：

- 你搜一个产品 → 看到它的生产厂家 → 看到该厂家的**双休指数**
- 你可以**上传**你掌握的厂家作息情报
- 你可以在厂家页面**评论**、补充、质疑

> **本站不采集、不爬取任何企业数据，也没有官方数据源。所有结论 100% 来自用户上传。**
> 因此「查不到」是常态，而每一条你上传的信息都会立刻改变别人的搜索结果。

## 功能

| 功能 | 说明 |
| --- | --- |
| **搜索** | 搜产品名 / 品牌 / 厂家名。名称会自动归一化（忽略空格、标点、「有限公司」等后缀），「晨光1.8L电热水壶」和「晨光 1.8L 电热水壶」是同一个东西 |
| **厂家页** | 双休指数（等级 A–E + 0–100 分）、休息情况分布、全部情报、全部评论 |
| **上传情报** | 双休 / 基本双休 / 大小周 / 单休 / 无休 / 说不清，外加作息、每周休息天数、工时、加班、调休、岗位、在职状态、佐证链接 |
| **评论** | 匿名昵称即可发表，可对已有情报提出异议 |
| **身份系统** | 三种入口：注册账号（一步到位）、账号密码登录、或只填昵称直接开始；游客身份可随时升级为账号 |
| **内容自管** | 自己写的评论可编辑/删除，情报、产品关联、以及自己建立的厂家条目都可删除；`/me` 汇总我的贡献 |
| **建立关联** | 用户可以提交「产品 → 厂家」的对应关系，也能新建厂家条目 |
| **地区封锁** | 屏蔽中国大陆（`CN`）IP，港澳台不受影响 |
| **移动端** | 响应式布局：窄屏单列、导航横向滚动、主按钮整行、输入字号 16px（防 iOS 聚焦缩放）、刘海屏安全区适配 |
| **零依赖** | 无任何第三方运行时依赖，无需构建步骤，`node src/server.js` 即可运行 |
| **双运行时** | 同一份业务代码跑在 Node（本地/自托管）和 Cloudflare Workers（边缘）上 |

## 快速开始

需要 **Node.js ≥ 23.4**（用到内置的 `node:sqlite`，这是它免 `--experimental-sqlite` 标志的最低版本；开发与测试在 Node 24 上完成）。**不需要 `npm install`。**

```bash
# 启动（首次会自动建库、建表）
node src/server.js

# 打开 http://127.0.0.1:8787
```

运行测试（会自动用**独立数据库**起一个测试服务，不碰你的正式数据）：

```bash
npm test      # 三个套件：主流程 + 移动端适配 + 身份与权限
```

## 你的数据存在哪里

**所有用户数据都在一个文件里：`data/xiumuxuan.db`**（SQLite）。

- **改代码、重启服务、升级版本都不会动它。** 表结构变化靠幂等的
  `CREATE TABLE IF NOT EXISTS` 加自动补列处理，不会重建表、不会清空数据。
- **备份**：停掉服务，把 `data/` 整个目录拷走就行
  （`xiumuxuan.db` 以及同目录的 `-wal` / `-shm` 三个文件）。
- **清空**：只有你显式运行才会执行——
  ```bash
  node scripts/reset-data.js        # 只报告现状，不动任何数据
  node scripts/reset-data.js --yes  # 确认后清空
  ```
- **跑测试不碰它**：`npm test` 会另起一个用 `data/test-run.db` 的服务（端口 8788），
  跑完自动删掉测试库。正式库全程只读不写。

> 部署到 Cloudflare Workers 时，数据在你的 D1 数据库里，同样不受代码更新影响。

想让别人也能打开（临时公网地址，**不需要 Cloudflare 账号**）：

```bash
npm run tunnel    # 自动准备 cloudflared 并打印 https://xxx.trycloudflare.com
```

### 常用环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DB_PATH` | `./data/xiumuxuan.db` | SQLite 文件路径 |
| `BLOCKED_COUNTRIES` | `CN` | 被封锁的国家/地区码，逗号分隔 |
| `GEO_POLICY` | `fail-open` | 拿不到国家码时：`fail-open` 放行 / `fail-closed` 拒绝 |
| `GEO_DEBUG` | 非生产环境为 `1` | 允许用 `?__geo=CN` 模拟来源地区。**生产必须为 `0`** |
| `IP_SALT` | 开发用默认值 | IP 哈希盐值，**生产必须改成随机长字符串** |

## 身份：注册、登录，或直接开始

`/login` 上有三个入口，按情况选一个：

| 入口 | 什么时候用 | 会发生什么 |
| --- | --- | --- |
| **注册新账号** | 第一次来，希望身份以后能找回 | 填用户名 + 密码（昵称可留空，默认用用户名）→ 立刻登录，账号当场生效 |
| **已有账号** | 之前注册过 | 用户名 + 密码 → 找回身份，连同全部已发布内容和编辑权 |
| **不注册，直接开始** | 只想发条情报，不想留凭据 | 填个昵称就能发布，但身份只活在当前浏览器的 Cookie 里 |

已经用游客身份发过内容的人，可以随时到 `/account` 补设用户名和密码，
把当前身份升级成账号——已发布的内容会一并归到这个账号下。

### 两种身份状态的差别

| | 游客身份 | 已设账号密码 |
| --- | --- | --- |
| 怎么获得 | 填个昵称即可 | 注册，或在 `/account` 补设 |
| 发布内容 | ✅ | ✅ |
| 管理自己发布的内容 | ✅ | ✅ |
| 换了设备 / 清了 Cookie | **身份永久丢失**：内容还在，但再也无法管理 | 用用户名密码登录即可找回 |
| 登出 | 等于放弃这个身份 | 可以再登录回来 |

登出按钮的确认文案会跟着变：没设密码时警告「退出后无法再登录」，
设了就变成「可以用密码重新登录」——因为它确实不一样了。

### 能管理自己的哪些内容

| 内容 | 自己能做什么 |
| --- | --- |
| 评论 | 编辑、删除 |
| 双休情报 | 删除 |
| 产品关联 | 删除 |
| 厂家条目 | 删除自己建立的条目 |

别人看不到这些按钮；服务端同样会校验归属，直接改 URL 提交会被拒。

**关于删除厂家**：厂家是个「容器」，删掉它会**连带删除**挂在它下面的情报、评论和产品关联
——其中可能包含别人贡献的内容。所以删除前页面会先把影响面算给你看：

```
删除会连带删除它下面的 3 条情报、5 条评论、2 个产品关联
——其中可能包含其他人贡献的内容。此操作不可撤销。
```

只有建立者本人能删；非建立者既看不到面板，直接 POST 也会被拒。
无人认领的历史条目（`user_id` 为空）任何用户都删不了。

### 实现要点

- 会话令牌是 32 字节随机值，**数据库只存 SHA-256 哈希**，明文只在响应里下发一次
- 令牌放在 `HttpOnly` + `SameSite=Lax` 的 cookie 里，HTTPS 下自动加 `Secure`
- **登出会在服务端撤销令牌**（替换为随机值），旧 cookie 立刻失效，而不是只清浏览器 cookie
- **用密码登录时轮换令牌**，防会话固定（session fixation）
- 密码用 **PBKDF2-SHA256 + 每用户独立随机盐**派生；迭代次数**存在用户记录里**，
  所以调整默认值只影响新注册用户，不会把老用户锁在门外
- 登录失败不区分「用户名不存在」与「密码错误」；对不存在的用户名也做一次等量派生，
  避免通过响应时间枚举出哪些用户名已注册
- 跳转参数 `next` 只接受站内路径，防止开放重定向
- 页面上的署名跟随身份，不允许在表单里改成别人的名字

### 代价与边界（诚实地说）

- **忘记密码就找不回来了。** 没有邮箱验证、没有找回流程——本站不收集任何联系方式。
- **用户名设置后不能改**，避免身份混乱。
- 只能防止误操作与随手篡改，**不能防恶意冒充**：任何人都可以填一个和你相同的昵称。
  真要防就需要邮箱或第三方登录，那又与「不收集个人信息」冲突。这是有意的取舍。
- 即使完全不登录也能上传情报和发表评论，只是发布之后无法再修改。

## 拿到一个可用的网址

### 方式一：临时公网地址（最快，无需账号）

```bash
npm start            # 终端 A：启动站点
npm run tunnel       # 终端 B：套一层 Cloudflare 隧道，打印公网地址
```

会得到形如 `https://xxx-xxx-xxx.trycloudflare.com` 的 HTTPS 地址。
它走 Cloudflare 边缘，所以服务器能拿到真实的 `CF-IPCountry`，**中国大陆 IP 打开会看到 403**。

局限：地址随机、每次启动都变、Cloudflare 官方不保证在线时长，关掉窗口即失效。适合演示与临时分享。

### 方式二：固定地址（推荐长期使用）

部署到 Cloudflare Workers + D1，得到一个永久的 `https://<你的域名>` 地址，
同时获得最可靠的地理封锁（边缘 WAF 拦截）。一条命令流程：

```bash
wrangler d1 create xiumuxuan     # 把返回的 database_id 填进 wrangler.toml
wrangler secret put IP_SALT      # 设置 IP 哈希盐值
wrangler deploy                  # 部署
```

完整步骤、WAF 国家封锁规则、验证清单与排错见 **[`docs/DEPLOY-CLOUDFLARE.md`](docs/DEPLOY-CLOUDFLARE.md)**。

## 中国大陆 IP 封锁

三层防护，逐层收紧：

### 第 1 层：Cloudflare WAF 国家封锁（推荐，最彻底）

在 Cloudflare 控制台 → 你的域名 → **Security → WAF → Custom rules** 新建规则：

- **Expression**：`(ip.geoip.country eq "CN")`
- **Action**：`Block`

这条规则在**网络边缘**就拦掉，请求根本不会到达 Workers，因此不消耗配额，也无法被应用层绕过。配置细节见 [`docs/DEPLOY-CLOUDFLARE.md`](docs/DEPLOY-CLOUDFLARE.md)。

### 第 2 层：应用层国家码校验

`src/geo.js` 会读取：

- Cloudflare Workers：`request.cf.country`（由边缘注入，**客户端无法伪造**）
- 挂在 Cloudflare 代理之后的自建服务：`CF-IPCountry` 请求头
- 自建反代：可自行注入 `X-Country-Code`

命中封锁列表即返回一个**什么都不说的 403**：纯文本 `403 Forbidden`，带 `noindex` 与 `no-store`。
不回显地区码、不出现站点名、不解释拦截原因——封锁页上的每一句说明，对来访者都是情报。
任何路径、任何方法都会被拦（包括表单提交），诊断线索只写进服务端日志。

Cloudflare 对**香港返回 `HK`、澳门 `MO`、台湾 `TW`**，所以封锁 `CN` 精确对应「中国大陆」，不会误伤港澳台。

### 第 3 层：fail-closed 兜底（可选）

如果你完全自托管、且没有 Cloudflare 代理，可以设 `GEO_POLICY=fail-closed`：
**只要拿不到国家码就一律拒绝**。此时本地开发请保留 `GEO_DEBUG=1`，否则连自己都会被挡在门外。

### 本地怎么验证封锁生效

```bash
curl -i "http://127.0.0.1:8787/?__geo=CN"   # → 403
curl -i "http://127.0.0.1:8787/?__geo=HK"   # → 200（港澳台不受影响）
curl -i "http://127.0.0.1:8787/?__geo=US"   # → 200
```

> `?__geo=` 只在 `GEO_DEBUG=1` 时生效，且仅用于本地开发。生产环境必须关闭，
> 否则在没有 Cloudflare 头的场景下会被伪造绕过。

## 双休指数怎么算

每个人的说法都换算成一个 0–1 的分数：

| 每周实际休息情况 | 分数 |
| --- | --- |
| 双休 | 1.00 |
| 基本双休（偶有周末加班但可调休） | 0.85 |
| 大小周 | 0.40 |
| 单休 | 0.10 |
| 无休 / 全月无休 | 0.00 |
| 说不清 / 变动大 | 不计入评分 |

加权平均时，每条情报的权重只由**新鲜度**决定：按 **400 天半衰期**衰减，越近的情报越重。

> 早期版本还按「信息来源」（本人亲历 / 亲友同事 / 公开招聘信息）再乘一个可信度权重。
> 该维度已取消——本站**不问来源**，所有情报一视同仁，
> 防刷改由提交频率限制、内容去重与「少于 3 条不给等级」的样本门槛承担。

等级：`≥85 → A`，`≥70 → B`，`≥50 → C`，`≥30 → D`，其余 `E`。

> **有效情报少于 3 条时，本站不给等级**，只显示「样本不足」。
> 一两个人的说法不足以定义一个厂家——这是刻意的设计，不是缺陷。

算法实现在 `src/logic.js` 的 `computeIndex()`，可以单独测试与替换。

│  ├─ html.js          html`` 模板（自动 HTML 转义，替代 hono/html）
│  ├─ views.js         全部页面

│  ├─ smoke-test.js        主流程端到端测试
│  ├─ auth-test.js         身份与权限端到端测试

│  └─ gen-schema-sql.js    由 src/schema.js 生成 schema.sql

**为什么不用框架？** 本项目刻意保持零运行时依赖：不需要 `npm install`、没有构建步骤、
`node src/server.js` 就能跑。业务代码全部基于 Web 标准的 `Request`/`Response`，
因此同一份代码在 Node 和 Workers 上行为一致。

## 防滥用与隐私

**隐私**

- **不保存明文 IP**。只保存 `SHA-256(盐 + IP)` 的前 12 字节十六进制，用于防刷，无法反推。
- 不提供账号系统，不留 cookie，不接入任何第三方统计或广告脚本。
- 页面统一带 `referrer: no-referrer`，对外链不加 referrer。
- 页面上明确提醒用户不要填写真实姓名、工号等可识别个人身份的信息。

**防滥用**

| 手段 | 说明 |
| --- | --- |
| 频率限制 | 每个 IP 哈希：情报 5 条/小时、评论 12 条/小时、厂家 5 个/小时、产品 8 条/小时（可在 `logic.js` 的 `RATE_LIMITS` 调整） |
| 登录限流 | 账号登录 10 次 / 15 分钟，注册 8 次 / 小时，设置或修改密码 5 次 / 小时，游客登录 10 次 / 小时 |
| 内容级去重 | 同 IP 在同厂家下提交**实质相同**的内容才会被拒。刻意不做「同厂家同 IP 一律拒绝」——同一个人的情况本来就可能要补充多条 |
| 蜜罐字段 | 表单里有一个对真人隐藏的 `website_hp` 输入框，被填写则内容直接丢弃 |
| 输入校验 | 字段长度、数值范围、链接协议、在职状态白名单 |
| XSS | 自研 `html\`\`` 模板对所有插值自动转义（`src/html.js`），只有显式 `raw()` 才原样输出 |
| 样本门槛 | 有效情报 < 3 条不给等级，提高灌水成本 |

## 参考的开源项目

动手前先调研了同类开源项目，取舍如下：

| 项目 | 借鉴了什么 | 为什么没有直接采用 |

## 已知局限

诚实地说清楚这个站点做不到什么：

1. **地理封锁不是绝对的。** 它基于 IP 定位。身处中国大陆的用户使用境外 VPN / 代理仍然可以访问，我们无法也没有试图做到物理隔绝。Cloudflare 的 IP 国家库本身也存在少量误判。
2. **数据未经核实。** 本站不审核任何上传内容，也不区分信息来源。一家公司可能被前员工报复性差评，也可能被公关刷好评——频率限制、内容去重与样本门槛只是缓解，不是根治。
3. **同一厂家内部差异巨大。** 办公室双休、产线大小周是常态。上传时写清部门和岗位，比什么都重要。
4. **没设密码的游客身份无法找回，也没有举报与申诉入口。** 设了账号密码就能登录回来；但若一直以游客身份使用，清除 Cookie 就等于永久失去身份，连同对自己内容的编辑权。另外，被恶意差评的厂家无处申辩——这是下一步最该补的。
